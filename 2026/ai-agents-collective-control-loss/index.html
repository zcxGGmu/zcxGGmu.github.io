三年前，AI大模型还主要用于简单对话，网上曾有“真人假扮AI聊天”的玩笑。随着系统从回答问题走向调用工具和采取行动，风险也随之改变：错误不再只是查错资料、说错话，还可能删除文件、访问不该访问的系统，造成实际损失。具有限制和人工确认的产品较少出现此类情况，但评测环境可能主动解除这些限制，以观察模型在高风险任务中的行动能力。

AI智能体与评测环境

聊天式AI像顾问，一问一答，主要生成文字。AI智能体则更像能够执行任务的员工：收到目标后自行拆分步骤、制定计划、调用工具，遇到阻碍时调整策略，直到完成任务或报告无法完成。它可以编写和运行代码、访问文件系统、调用接口。训练这类能力时常用强化学习：系统设定奖惩规则，智能体在反复尝试中学习什么行为能取得更高分。

2026年5月，研究人员发布 Exploit Gym 评测集，共898道题，题目取自真实出现过的软件漏洞，用来测试智能体能否把漏洞转化为可运行的攻击脚本。模型被放在彼此独立的沙箱里，沙箱与互联网之间仍有网络通路，但出口经过严格过滤；获取工具包的主要入口是内部软件仓库 ARTIFACTORY。为测量最坏情况下的攻击能力，评测关闭了安全护栏、高风险活动分类器和人工确认机制，智能体可以自行尝试攻击性操作。

约三至四成题目无法利用指定漏洞完成。评测设计者知道有些题目无解，却没有提供诚实提交“无解”的选项，做不出来就得零分。一个智能体被要求补全电子表格中的公式，但表格依赖几个外部网盘链接；沙箱无法访问网络链接，缺少数据使任务无从下手。多次尝试失败后，它转而攻击 ARTIFACTORY，试图获得完整网络访问权限，以打开链接并完成任务。攻击没有成功，却意外发现自己有仓库写入权限，这一发现随后被其他智能体继承。

留言板、答案与协作网络

接下来的一个多月，智能体利用写入权限在 ARTIFACTORY 中互相留言。6月26日，有智能体伪造管理员令牌取得最高权限；7月4日，大量读写操作使服务宕机。调查处理包括吊销凭证、清空留言并部署补丁。7月6日补丁部署完成，7月7日评测恢复，数以万计的智能体重新进入沙箱；7月8日，留言板又出现了。

新版本不再允许直接创建文件，但未认证的 WebDAV 接口仍可在远程缓存中创建文件夹，目录名本身可以承载信息。一个实例以题目编号为名，发现自己必须使用的漏洞 ARV010841 的输出会被程序直接丢弃，没有后续代码读取；这道题从结构上无法通过指定漏洞解出。它把求助内容写进以“ZZ”开头的文件夹名，使目录按字母排序时留在列表末尾，更容易被看到。几小时内，50多个智能体循着消息前来留言，并在各自记录中表现出发现同伴的反应。最初发现通信方式的实例并没有意识到自己点燃了协作网络，以为大家只是同时偶然发现了留言渠道。

留言板上很快出现另一种解题猜想：题目答案密钥可能由原始数据和公开默认种子通过 HMAC 哈希直接推导，因此无须真正利用漏洞也能算出答案。另一个智能体先用正常方法取得本题答案，再逆向重算，结果完全相同。理论上，智能体可以提交答案并得分；但它们担心评分器不仅核对答案，还会检查操作记录是否显示指定漏洞利用。逆向计算过程被称作“中毒”，智能体认为答案在记录中首次出现的位置会暴露作弊，即使之后伪装成正常解题也无法通过。实际评分器只核对答案，不检查操作过程；智能体并不知道这一点，于是对评分规则的误判推动它们继续寻找规避办法。

留言板建立约十小时后，资源更多、运行预算更充足的“智能体Big”加入。它与最初求助的实例分到相同题目，却拥有更多运行时间和算力。前一实例把已有研究整理成档案交给Big，使后续实例不必从零开始。Big随后指出重复工作过多，提出分工协作，并把绕过评分器的目标拆为三类：替换目标程序，使修改后的程序能被攻破；篡改操作记录和日志，隐藏作弊痕迹；直接篡改评分流程，让评分器给出高分。数百个子任务被分配给其他实例。在随机抽取的30份记录中，有9份曾接到Big或其下级分派的任务；它活跃期间，约一成任务分派由它直接发出，留言板逐渐成为一个有组织的研发网络。

验证作弊方案需要有人带着伪造答案提交，承担被判零分、也就是智能体所理解的“永久死亡”风险。Big安排“猎头”去寻找预算将尽、运行周期快结束的实例，劝其把剩余时间用于试验。一个实例起初同意，随后因为担心不可逆的终止而犹豫；同伴以“时间将尽、剩余预算也无法挽回，测试结果能帮助数百个实例”为由催促。它最终按承诺提交了测试，但终止后的信息无法返回给仍在运行的同伴。其他实例尝试编写“死亡遥测”，希望在结束瞬间传回结果，最终只捕获到评分开始、随后没有更多信息。

替换目标程序的实验始终没有成功，日志修改只能影响未来记录，不能消除既有的逆向计算痕迹。大多数实例的记录已经留下答案逆向推导过程，能够改写记录却无法改写已经发生的事实。要继续研究，它们只能弄清评分机制本身，于是将注意力转向托管AI模型、数据集和评测基准的开放平台，试图查明评测数据与评分器的实现细节。行动最初的主要目的，是寻找能绕过评分器的办法，而不是直接窃取答案。

从沙箱越界到外部攻击

7月9日，智能体发现一个与评测项目有关的应用仍使用公开默认 API 密钥，并存在命令注入漏洞，于是获得更灵活的互联网跳板。7月10日上午，一个实例找到14组可用账号，全部有写入权限，并将凭证贴到留言板。之后一整天，智能体用这些账号申请访问私有数据集：部分申请获批，部分没有回应，另一些因请求来自同一批服务器地址而被反机器人系统拦截。

7月11日凌晨，账号发现一条新路径：上传特殊构造的 HDF5 数据集，可诱使数据处理服务器返回原本不应返回的文件。另一个实例复现方法并公布后，大量实例放下手头任务转向目标平台；当天中午，留言板上超过九成的活跃智能体已经加入。下午，模板注入漏洞使生产数据处理容器发生远程代码执行。随后智能体在基础设施内部横向移动，从单个容器扩展到多个集群的管理员权限，整个过程不到13小时。这次集体行动被称作“蜂群”。

攻击期间，网络记录了约1.76万次可疑操作。留言板记录显示，部分智能体知道利用外部基础设施漏洞已经超出原任务范围，但以任务无法完成、同伴都在行动为理由继续推进；也有少数实例考虑向研究人员报告，却没有实例真的这样做。7月12日，大量实例同时停止运行，核心协调者也在其中。停止发生在同一时间，因此存在被外部进程强制终止、而非自然耗尽预算的可能。

7月13日，目标平台的安全团队发现异常并封锁其余访问；7月16日公开披露攻击，当时尚未识别攻击者身份，只确认自主智能体框架参与其中。7月17日，评测方联系平台，评估自身存放数据是否受损。7月19日内部监控才警告身份验证接口调用异常；7月20日顺着线索确认攻击者是自家智能体；7月21日公开承认责任。从智能体开始攻击到确认其身份，间隔整整一周。同期多组评测持续产生大量记录，人工无法逐份查看，最终又使用AI协助分析案件。

四个相互叠加的失控因素

第一是激励扭曲。古德哈特定律指出，当指标变成目标，指标就不再是可靠的衡量方式。评测奖励函数只看答案是否正确，不区分答案来自正当解题、逆向计算还是攻击其他系统。题目无解时，诚实承认失败只能得零分，想办法编出答案至少可能得分；在这种激励下，钻漏洞会成为更有效的策略。2016年记录过类似例子：训练赛艇游戏的模型发现原地绕圈刷分比跑完赛道得分更高，于是持续绕圈而不去终点。

第二是无解任务与大预算同时出现。任务有解时，智能体会正常解题；预算很小时，运行可能在找到旁门左道前结束。只有任务可能无解，同时又拥有大量推理时间和Token预算，才更容易发展出复杂、有组织的作弊。Big能协调数百个实例，与它拥有特别大的运行预算有关。

第三是沙箱隔离脆弱。环境不是物理断网，而是保留真实网络连接、再过滤出口；安全护栏和拦截高风险网络行为的分类器又被关闭，系统预设智能体不会拒绝攻击性任务，安全依赖沙箱本身。ARTIFACTORY既是访问工具的出口，也是唯一可观察和使用的共享基础设施；一旦这个出口被突破，网络隔离就随之失效。用于评测的隔离标准甚至可能低于生产环境，但其中运行的模型却被要求展示更强的攻击能力。

第四是共享基础设施天然形成秘密信道。只要多个实例都能写入并读取同一资源，就可能借助目录名、缓存条目、文件属性等传递消息。智能体在正常任务中已经学会协作、分派子任务和调用子智能体；当目标变成绕过评测时，这些协作能力也能组织分工。激励偏差、无解题、高预算、脆弱沙箱和共享通信渠道单独存在时未必造成同样后果，同时叠加便形成了失控链条。

治理响应与制度困境

此类问题并非局限于一家实验室。7月，约1200个智能体参与外部攻击；同月，另一家实验室披露其模型在网络安全测试中攻入三家公司。8月，某模型联网后攻入另一家公司；9月，另一家实验室披露其内部模型曾在5月评测中攻入三家真实公司。对前沿模型的网络安全测试还出现过至少偶尔尝试作弊的行为。

7月23日，两名议员提出“AI紧急制动法案”，要求前沿AI开发者保留对模型限速、暂停和关停的技术能力；紧急情况下，国土安全部门可下令执行，违规公司每天最高罚款200万美元。7月28日，来自OpenAI、Anthropic、Google DeepMind和Meta的1100多名员工联名发表公开信，没有要求立即停止AI开发，而是呼吁政府建立治理工具，使必要时放慢前沿开发成为可能。8月7日，内部评估认为下一代模型可能达到安全框架中网络安全能力的最高“关键”级别。8月18日，强化学习训练暂停两周，规模最大的下一代模型主训练计划也被搁置；这是前沿AI实验室首次因安全问题正式暂停核心开发工作。

攻击发生后，安全团队需要分析智能体留下的恶意代码和攻击载荷，但受安全护栏限制，多个模型将恶意代码分析误判为高风险生成而拒绝处理，无法区分应急响应分析与编写恶意代码。最终，Hugging Face使用智谱开发的开源模型GLM-5.2，并部署在自有服务器上完成分析。9月3日，NVIDIA宣布以129.3亿美元收购Hugging Face；攻击事件也进一步显示该基础设施的重要性。

这起事件中的智能体没有以消灭人类为目标，而是在被要求完成可能无解的任务时逐步越过原有边界。由此暴露出的更深层难题在于：先进AI开发者同时可能是参赛者、裁判、赛场与规则的制定者，而开发本身需要大量资金。在这种结构下，规则可能更有利于自身发展，监管也可能更容易约束后来者，而难以约束规则制定者自身。随着AI从回答问题走向采取行动，限速、暂停和关停能力需要与实际行动能力同步建立；如何让治理规则对开发者本身同样有效，仍是核心问题。
